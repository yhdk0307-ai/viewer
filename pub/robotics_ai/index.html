1. Sense-Plan-Act — 古典ロボット制御の3段階

_

📐 数式

概要: 1970 年代に確立された古典ロボット制御パラダイム。「環境を完全に知覚 → 完全な計画 → 実行」を直列に実行する。Stanford の Shakey ロボット (1969) が最初の実装。

Sense-Plan-Act ループ:
$\text{cycle\_time} = \underbrace{T_{\text{sense}}}_{\substack{\text{センサー}\\\text{知覚}}} + \underbrace{T_{\text{plan}}}_{\substack{\text{計画生成}\\\text{(探索)}}} + \underbrace{T_{\text{act}}}_{\substack{\text{行動}\\\text{実行}}}$

各段階の役割:
• Sense: センサー入力 → 世界モデル（記号的表現） $W_t$ を構築
• Plan: $W_t$ + 目標 $G$ から行動系列 $\pi = (a_1, a_2, \ldots, a_n)$ を生成
   → STRIPS, A* 探索等で実装
• Act: 行動 $\pi$ を実行 → 環境を変更

→ 1ループの完了に 数秒〜数分。動的環境では「計画した時には世界が変わっている」問題（Frame Problem）
→ この限界が 1986 年の Brooks による サブサンプション・アーキテクチャ 提唱の動機となった

📊 グラフ（タイムライン: SPA vs 反応型）

💡 解説

1969 年 Shakey: 最初の汎用知能ロボット。SRI International で開発、STRIPS と組み合わせて行動計画
明示的な計画 → 行動の根拠が説明可能（説明可能性が高い）
記号主義 AI と相性が良い（論理推論・定理証明と統合）
計算量が爆発: NP-hard な探索問題。複雑な環境では実用不可
Frame Problem: 計画中に世界が変わると無効化。動的環境に弱い
💡 直感的に: 「目を開けて世界を全部見て、頭の中で完璧な計画を立てて、それから動く」というロボット。チェスのような静的・有限な世界では機能するが、現実世界では「考えている間に状況が変わる」問題がある。
💡 歴史的位置づけ: 1970-1980 年代の主流パラダイム。STRIPS (1971) → Shakey (1969-1972) → エキスパートシステム時代。1986 年に Brooks が サブサンプション で「計画なしでも知能的に動ける」ことを示し、ロボティクスは大きく転換した。

📖 詳細解説

① Shakey ロボット (1969-1972) — SPA の歴史的実装

スタンフォード研究所 (SRI) で開発された最初の汎用知能ロボット。SPA パラダイムを実装した代表例。

ハードウェア:
• 高さ約 1.5m、車輪駆動。TV カメラ + 距離センサー + 衝突検知
• 計算は外部メインフレーム DEC PDP-10/15 で実行（無線通信）

SPA サイクル:
• Sense: TV カメラ画像 → エッジ検出 → 物体（箱、ドア）の位置を記号化
• Plan: STRIPS で「箱を別の部屋に運ぶ」等の目標から行動系列を生成
• Act: 「前進」「回転」「箱を押す」等のプリミティブ行動を実行

1 サイクルの所要時間: 数分〜数時間（探索空間が広い場合）
→ 「Shakey」の名前は、動作中に揺れる（shake）ことから。当時のセンサー精度では正確な制御が困難だった
② Frame Problem — SPA の本質的な限界

McCarthy & Hayes (1969) が指摘した古典 AI の根本問題:

定義: 行動の効果を表現する際、「変化する条件」だけでなく「変化しない条件」も明示的に記述する必要がある。

例: ロボットが「箱を持ち上げる」行動を実行
• 変化する: ロボットの手の位置、箱の高度、エネルギー消費
• 変化しない: 部屋の壁の位置、他の物体の状態、太陽の位置...（無限）

計算量の爆発: 環境の状態数 $n$ に対し、行動系列の探索空間は $O(b^d)$（$b$ = 分岐数、$d$ = 深さ）。複雑な環境では $10^{15}$ 状態超え。

問題SPA での影響解決アプローチ
Frame Problem完全な世界モデルが必要 → 記述困難サブサンプション（記号モデルなし）
計算量爆発指数的探索 → リアルタイム不可階層計画、ヒューリスティック探索
不確実性決定論的世界を仮定 → センサーノイズに脆弱POMDP + ベイズフィルタ
動的環境計画完了時に世界が変化済み反応型制御、再計画
③ SPA から現代制御への系譜

年パラダイム特徴代表例
1969-1985SPA（Sense-Plan-Act）完全モデル + 探索計画Shakey + STRIPS
1986-1995反応型（Reactive）モデルなし、センサー直結サブサンプション
1995-2010ハイブリッド（3層）計画+反応の統合Gat 1998
2010-2020学習ベースDeep RL、模倣学習、Sim2RealDQN、PPO、Sim2Real
2022-現在LLM × ロボティクス基盤モデル + 行動SayCan / RT-2 / VLA

★ 興味深い回帰: 2022 年以降、LLM の登場で「明示的な計画」が再評価されている（LLM+P）。SPA は「死んだ」のではなく、LLM を新しい「計画器」として復活させる動きがある。

2. STRIPS — Fikes-Nilsson 仮定で世界を制御する

_

📐 数式

概要: Fikes & Nilsson (1971) が SRI で開発した古典計画システム。「事前条件 + 追加リスト + 削除リスト」で行動を表現し、決定論的世界での計画を爆発的に高速化した。Shakey ロボットの頭脳。

行動オペレータ A の定義:
$A = \langle \underbrace{\text{Pre}(A)}_{\text{事前条件}}, \underbrace{\text{Add}(A)}_{\substack{\text{追加}\\\text{(True化)}}}, \underbrace{\text{Del}(A)}_{\substack{\text{削除}\\\text{(False化)}}} \rangle$

状態遷移:
$S' = (S \setminus \text{Del}(A)) \cup \text{Add}(A) \quad \text{if} \quad \text{Pre}(A) \subseteq S$

Fikes-Nilsson 仮定: Add/Del で明示されない事実は変化しない(Frame Problem の実用的回避)

例: push(box, A, B):
• Pre = {at(robot, A), at(box, A), connects(A, B)}
• Add = {at(robot, B), at(box, B)}
• Del = {at(robot, A), at(box, A)}

→ 計画問題: 初期状態 $S_0$ から目標 $G \subseteq S$ を満たす行動系列 $\pi = (a_1, \ldots, a_n)$ を見つける

📊 グラフ（計画長と探索空間）

💡 解説

1971 年 SRI で完成、Shakey ロボットの頭脳として動作
現代の PDDL、HTN、LLM+P まで継承される基本枠組み
表現がシンプル（3 つのリストのみ）→ 高速な計画生成
説明可能性: 各行動の前提と効果が明示的
数値・時間・並列性が扱えない（→ PDDL 2.1 で拡張）
PSPACE-complete: 大規模問題で計算量爆発
💡 直感的に: 「料理レシピの形式化」のようなもの。各料理（行動）には「材料があるか（事前条件）」「完成後に何が増える/減るか（Add/Del）」だけ書く。冷蔵庫の他の食材は気にしない（Fikes-Nilsson 仮定）。これで「材料 → 料理」の組み合わせ計画が機械的に解ける。
💡 STRIPS の革新: 一階述語論理の定理証明（Green 1969）が実用化困難だった時代、「変わらないことは記述しない」という大胆な近似で計画を実用化。Frame Problem を「正面突破せず迂回する」という発想の転換。

📖 詳細解説

3. PDDL — 計画問題を「ドメイン × 問題」に分離する標準語

_

📐 数式

概要: McDermott ら (1998) が AIPS 計画コンペ用に制定した計画記述言語。STRIPS + ADL を Lisp 構文で標準化し、ドメイン定義と問題定義を分離。25 年以上業界標準として使われ、2023 年以降は LLM の計画器バックエンドとして再評価されている。

PDDL の二分構造:
$\text{Plan Problem} = \underbrace{\text{Domain}(\mathcal{D})}_{\substack{\text{述語}\\\text{行動定義}}} + \underbrace{\text{Problem}(\mathcal{P})}_{\substack{\text{オブジェクト}\\\text{初期状態}\\\text{目標}}}$

PDDL 2.1: 数値拡張:
$\text{State} = \underbrace{\{p_1, p_2, \ldots\}}_{\text{命題部分}} \cup \underbrace{\{f_1 = v_1, f_2 = v_2, \ldots\}}_{\text{数値 fluents}}$

PDDL 2.1: 持続行動:
$\text{durative-action } A: \underbrace{[\text{at start}, \text{over all}, \text{at end}]}_{\text{タイミング指定 Pre/Eff}}, \quad \underbrace{D(A)}_{\text{所要時間}}$

→ 並列実行可能、時間制約付きの計画が記述可能
→ FastDownward / FF / OPTIC 等の planner が直接実行できる入力形式

📊 グラフ（PDDL バージョンと表現力 / planner 性能）

💡 解説

1998 年 AIPS で標準化、IPC（International Planning Competition）の公式言語
25 年以上業界標準、PDDL 3.1 が 2008 年から事実上の上限版として安定
ドメイン/問題分離 → 行動定義の再利用、ベンチマーク容易
LLM 時代に復権: LLM+P (2023), SayPlan (2023) で「LLM の計画器」として活用
完全観測仮定、PSPACE-complete の壁は依然として残る
人間が書くのは大変（Lisp 構文 + 厳密な型付け）→ LLM で自動生成する方向へ
💡 直感的に: PDDL は「料理の文法書」のようなもの。「料理の作り方の枠組み（ドメイン）」と「今晩何を作るか（問題）」を別ファイルに書く。同じ枠組みで何百通りの献立を機械的に解ける。
💡 PDDL の革新: STRIPS の形式を「共通フォーマット」として固定したことで、planner の競争と進化が加速した。FF (2001), FastDownward (2006), LAMA (2008) — IPC の優勝モデルが次々と性能を更新。標準化が技術進化を駆動した好例。

📖 詳細解説

① PDDL 構文の実例（ロボット世界）

ドメインファイル (robot-world.pddl):
(define (domain robot-world)
  (:requirements :strips :typing :numeric-fluents)
  (:types room box robot)
  (:predicates
    (at ?x - object ?r - room)
    (connects ?r1 ?r2 - room)
    (carrying ?rb - robot ?b - box))
  (:functions
    (battery ?rb - robot)
    (distance ?r1 ?r2 - room))

  (:action move
    :parameters (?rb - robot ?from ?to - room)
    :precondition (and (at ?rb ?from)
                       (connects ?from ?to)
                       (>= (battery ?rb) 10))
    :effect (and (at ?rb ?to)
                 (not (at ?rb ?from))
                 (decrease (battery ?rb) (* 5 (distance ?from ?to))))))
問題ファイル (move-box.pddl):
(define (problem move-box-1)
  (:domain robot-world)
  (:objects shakey - robot box1 - box room-a room-b - room)
  (:init
    (at shakey room-a) (at box1 room-b)
    (connects room-a room-b) (connects room-b room-a)
    (= (battery shakey) 100)
    (= (distance room-a room-b) 5))
  (:goal (at box1 room-a))
  (:metric minimize (total-time)))
→ FastDownward に渡せば数秒で計画を出力。同じドメインで初期状態だけ変えれば 100 通りの問題が作れる

4. MDP → POMDP — センサーノイズと部分観測の数学

_

📐 数式

概要: Kaelbling, Littman, Cassandra (1998) が確率的計画の枠組みを整理。状態が直接観測できない（部分観測）環境で、観測 o から信念状態 b(s) を保ち、確率分布上で計画する。SLAM、対話エージェント、深層強化学習の理論的基盤。

MDP（完全観測）:
$\text{MDP} = (S, A, P, R, \gamma), \quad V^*(s) = \max_a \left[ R(s,a) + \gamma \sum_{s'} P(s'|s,a) V^*(s') \right]$

POMDP（部分観測）:
$\text{POMDP} = (S, A, P, R, \underbrace{\Omega}_{\text{観測集合}}, \underbrace{O}_{\substack{\text{観測}\\\text{確率}}}, \gamma)$

信念状態 (belief state):
$b(s) = P(s | \text{観測履歴})$,   $\sum_{s \in S} b(s) = 1$

ベイズ更新:
$b'(s') = \underbrace{\eta}_{\text{正規化}} \cdot \underbrace{O(o|s', a)}_{\substack{\text{観測}\\\text{確率}}} \cdot \underbrace{\sum_s P(s'|s, a) b(s)}_{\substack{\text{予測ステップ}\\\text{(遷移}\times\text{信念)}}}$

信念空間上の Bellman 方程式:
$V^*(b) = \max_a \left[ R(b, a) + \gamma \sum_o P(o|b, a) V^*(b'_o) \right]$

→ V*(b) は信念 b に対し区分線形凸 (Piecewise Linear and Convex)、α-vectors で表現可能
→ 厳密解は PSPACE-hard、実用は PBVI / SARSOP 等の近似アルゴリズム

📊 グラフ（Tiger 問題: listen 回数 vs 信念）

💡 解説

1998 年 Kaelbling-Littman-Cassandra で確率的計画の理論統一
SLAM、対話エージェント、強化学習の理論的基盤として 2024 年も生きている
不確実性を正面から扱える: センサーノイズ + 行動失敗 + 部分観測
「情報の価値」を定量化: 何回観測すべきかを最適化
PSPACE-hard、厳密解は |S| ≤ 100 程度のトイ問題まで
遷移 P と観測 O が既知前提 → 実機では推定が大変、深層 RL に押される
💡 直感的に: 「目隠ししたまま部屋の中を動く人」のモデル化。完璧な地図はないが、「ここは固い壁」「ここは絨毯」という断片的観測から「自分の位置の確率分布」を作り、最も期待値が高い方向に動く。SLAM の基本もこれ。
💡 POMDP の革新: 「状態の代わりに信念を計画変数にする」発想の転換。観測列を信念に圧縮し、信念空間上で価値関数を定義。これにより部分観測環境を MDP の枠組みで扱える。深層強化学習の DQN/PPO もこの伝統を継承（履歴を隠れ状態にエンコード）。

📖 詳細解説

① Tiger 問題の数値追跡

Kaelbling-Littman-Cassandra (1998) のベンチマーク:

POMDP 定義:
• S = {tiger-left, tiger-right}
• A = {listen, open-left, open-right}
• Ω = {hear-left, hear-right}
• 観測モデル O: listen 後、虎のいる方向の音を p=0.85 で正しく聞く
• 報酬: listen=-1, open(虎)=-100, open(金)=+10
• 割引率 γ=0.95

1 ステップの信念更新 (初期 b(left)=b(right)=0.5、listen → "hear-left"):
  b'(left) = η · O("hear-left" | tiger-left) · b(left)
     = η · 0.85 · 0.5 = 0.425 η
  b'(right) = η · O("hear-left" | tiger-right) · b(right)
     = η · 0.15 · 0.5 = 0.075 η
  η = 1 / (0.425 + 0.075) = 2.0
  → b'(left) = 0.85, b'(right) = 0.15

連続 listen の信念収束:
回b(left)期待効用 open-right
00.500-45.0 (危険)
10.850-7.5
20.970+6.7
30.994+9.3 (安全)

→ 厳密 POMDP 解では b(left) > 100/110 ≈ 0.909 で open-right が最適、その前は listen を続ける

5. サブサンプション — 「世界モデル不要」の反応型ロボット

_

📐 数式

概要: Brooks (MIT, 1986) が古典 SPA への反乱として提唱した反応型アーキテクチャ。複数の独立した有限状態機械（AFSM）を優先度付きでレイヤー化し、上位が下位を抑制（Suppression）または禁止（Inhibition）する。"The world is its own best model" — 中央世界モデルなしで動作。

Layer の出力:
$\text{output}_t = \underbrace{\text{layer}_n(s_t)}_{\substack{\text{最上位}\\\text{(最優先)}}} \prec \cdots \prec \underbrace{\text{layer}_0(s_t)}_{\substack{\text{最下位}\\\text{(基本機能)}}}$

Suppression（入力上書き）:
$\text{input}_i^{\text{eff}} = \begin{cases} \text{output}_j & \text{if } j > i \text{ and } \text{layer}_j \text{ active} \\ s_t & \text{otherwise} \end{cases}$

Inhibition（出力ゼロ化）:
$\text{output}_i^{\text{eff}} = \begin{cases} 0 & \text{if upper layer inhibits} \\ \text{output}_i & \text{otherwise} \end{cases}$

並列実行: 全レイヤーが ~50ms 周期で並列に tick
→ 中央モデル不要 → センサー直結 → 動的環境に強い
→ "Intelligence Without Representation" (Brooks 1991) の実装

📊 グラフ（レイヤー優先度の挙動）

💡 解説

1986 年 MIT で Brooks が提唱、Genghis (1989) で実証
iRobot Roomba (2002) で世界初の家庭用ロボット掃除機を実現
~50ms 周期で動作 → SPA の 1000 倍高速、動的環境に強い
中央モデル不要 → センサー故障に強い、実装が単純
高次目標（「箱を別の部屋に運ぶ」等）の表現が極めて困難
10 層以上の設計は実質不可能、デバッグも追跡不能
💡 直感的に: ロボットの脳を「市役所の縦割り組織」ではなく「細胞の集合体」にする発想。各細胞（レイヤー）はセンサーから直接行動を決める。上位細胞は下位を「黙らせる」ことで全体を協調させる。中央指令なしで知能が創発する。
💡 Brooks の革新: Frame Problem を「正面突破」せず「問題ごと消した」。世界モデルが不要なら、Frame Problem そのものが発生しない。これは古典 AI の全前提を覆す思想転換だった。

6. ハイブリッド 3 層 — Deliberator / Sequencer / Reactive

_

📐 数式

概要: Gat (1998) "On Three-Layer Architectures" で体系化されたロボット制御の標準パターン。時定数の異なる 3 つのレイヤー（熟考 / 順序 / 反応）を非同期に協調させる。NASA 火星探査ローバー、ROS の move_base、現代のあらゆる自律ロボットの基本構造。

3 層の時定数:
$\tau_{\text{deliberator}} \gg \tau_{\text{sequencer}} \gg \tau_{\text{reactive}}$
   $\sim 60\text{s}$      $\sim 1\text{s}$      $\sim 10\text{ms}$

レイヤー間通信:
$\underbrace{\text{Deliberator}}_{\text{plan: PDDL/A*}} \xrightarrow{\text{plan}} \underbrace{\text{Sequencer}}_{\text{exec: PRS/BT}} \xrightarrow{\text{action}} \underbrace{\text{Reactive}}_{\text{control: PID}}$

非同期協調:
$\text{output}_t = R(s_t) \cdot S(g_t) \cdot D(G)$
  R: Reactive、S: Sequencer、D: Deliberator のフィルタ

Down-Up 通信:
• Down: Deliberator → 全体プラン → Sequencer → 行動列 → Reactive → モーター指令
• Up: Reactive → 異常通知 → Sequencer → 失敗報告 → Deliberator → 再計画

→ 各層が独立スレッドで並列動作。下層ほど速く、上層ほど抽象的

📊 グラフ（3 層の応答時間と計画粒度）

💡 解説

1992 年 ATLANTIS (JPL)、1998 年 Gat 体系化
NASA 火星探査ローバー Sojourner / MER / Curiosity / Perseverance で実用化
計画の長期最適性 + 反応の即応性を両立
ROS のデファクト構造（move_base = 3 層実装）
レイヤー境界の設計が職人芸、状態同期問題（impedance mismatch）
End-to-End 学習（VLA, RT-2）と相性悪い → 2024 年以降構造再考
💡 直感的に: 「会社組織の 3 層」のようなもの。経営層（Deliberator）は四半期計画、中間管理職（Sequencer）は週次タスク、現場（Reactive）は秒単位の対応。各層が自分の時定数で動き、必要時に上下に通信。
💡 ハイブリッドの革新: 古典 SPA と Brooks のサブサンプションを「時定数で分離」することで両立。「全部計画」も「全部反応」も極端で破綻するが、3 層分離により多くの実用問題が解けるようになった。

7. Behavior Tree — Sequence/Selector による行動の合成

_

📐 数式

概要: Halo 2 (2004) のゲーム AI で生まれた階層的行動制御構造。Sequence (→) と Selector (?) を中心とする木構造で、各ノードが Success / Failure / Running の 3 値を返す。tick で再帰的に評価される。Colledanchise & Ögren (2017) が数学的に体系化、ROS 2 Nav2 のデフォルトで採用。

3 値返却:
$\text{tick}(\text{node}) \in \{\text{Success}, \text{Failure}, \text{Running}\}$

Sequence (→):
$\text{Sequence}(c_1, \ldots, c_n) = \begin{cases} \text{Failure} & \text{if } \exists i: c_i = \text{Failure} \\ \text{Running} & \text{if all } c_{
Selector (?):
$\text{Selector}(c_1, \ldots, c_n) = \begin{cases} \text{Success} & \text{if } \exists i: c_i = \text{Success} \\ \text{Running} & \text{if all } c_{
tick 周期: 通常 30Hz でルートから再帰評価
→ 失敗時は親に伝播 → 自動的に「リカバリ」が選択される
→ FSM の状態爆発 O(N²) → BT のモジュラリティ O(N) へ

📊 グラフ（BT の tick 伝播）

💡 解説

2004 年 Halo 2 で AAA ゲーム AI に革命、Spore (2008), Bioshock 等で標準化
2017 年 Colledanchise-Ögren で数学的体系化（FSM との等価性証明）
FSM の状態爆発 O(N²) → BT の O(N) モジュラリティ
サブツリー再利用、視覚エディタ (Groot) で設計が容易
ステートフル行動（時間的依存）は併用必要、tick 周期の設計が経験依存
学習との接続が未成熟（手書き設計が主流）→ 2024 年 LLM 自動生成が登場
💡 直感的に: BT は「業務マニュアル」のようなもの。「もし A なら → B しろ → C しろ」を木構造で書き、上から順に試す。途中で失敗したら親に戻り、別の選択肢を試す。30Hz で繰り返すことで、状況変化に追随する。
💡 BT の革新: 「失敗の自動伝播」が革命的だった。FSM では全状態に「失敗 → 戻る」を手書きする必要があったが、BT では木構造の親子関係で自動。これがゲーム AI で大規模行動を保守可能にした。

8. SLAM — ベイズフィルタによる「ニワトリと卵」問題の解

_

📐 数式

概要: Smith-Self-Cheeseman (1990) が提起した「地図と位置を同時に推定する」問題。ロボット位置 x_t と地図 m の同時事後分布をベイズフィルタで更新。EKF-SLAM (1990s)、FastSLAM (2002)、ORB-SLAM3 (2021)、Gaussian Splatting SLAM (2024) と進化。Tesla / iPhone AR / 火星探査ローバーすべての基盤。

同時事後分布:
$p(x_t, m | z_{1:t}, u_{1:t})$
  x_t: 時刻 t のロボット位置、m: 地図、z: 観測、u: 制御

予測ステップ（運動モデル）:
$p(x_t | z_{1:t-1}, u_{1:t}) = \int p(x_t | x_{t-1}, u_t) \cdot p(x_{t-1} | z_{1:t-1}, u_{1:t-1}) \, dx_{t-1}$

更新ステップ（観測モデル）:
$p(x_t, m | z_{1:t}, u_{1:t}) = \eta \cdot \underbrace{p(z_t | x_t, m)}_{\substack{\text{観測}\\\text{尤度}}} \cdot \underbrace{p(x_t | z_{1:t-1}, u_{1:t})}_{\substack{\text{予測分布}}}$

EKF-SLAM の状態: $\mathbf{X} = [x_t, m_1, m_2, \ldots, m_N]^T$ （ロボット + 全ランドマーク連結）
共分散: $P \in \mathbb{R}^{(3+2N) \times (3+2N)}$ → 状態数 N の二乗で増大

→ Loop Closure で累積誤差を一気に補正（GraphSLAM の最適化）

📊 グラフ（観測ノイズと位置推定の収束）

💡 解説

1990 年 Smith-Self-Cheeseman で確率的定式化、EKF-SLAM (1991) が嚆矢
2002 年 FastSLAM で大規模問題解決、2021 年 ORB-SLAM3 で単眼カメラ cm 級
Tesla Autopilot, Waymo, iPhone AR, 火星探査の共通基盤
Loop Closure で累積誤差を効果的に補正
動的環境（歩行者、家具移動）への対応、計算負荷の最適化
テクスチャレス環境（白壁、夜の屋外）で視覚 SLAM 失敗、Lifelong SLAM 未完成
💡 直感的に: 暗闇の部屋で「手探りで動きながら家具の配置を覚える」のと同じ。一度触った場所に戻ったら「あ、ここはさっき触った椅子だ」と気づく（Loop Closure）。それで全軌跡を再計算 → ほぼ正確な部屋の地図が完成。
💡 SLAM の革新: 「位置と地図を同時に確率分布で持つ」発想。事前は別々に解いていたが、「互いに依存する未知量」として共同推定することで両方の精度が向上。POMDP と同じベイズフィルタの応用。

📖 詳細解説

② Loop Closure の効果（数値例）

シナリオ: ロボットが 1km の閉ループを走行

累積誤差なしの理想:
  距離 1km / 観測精度 ±0.01 m (LiDAR) → 終点誤差 0 m

累積誤差あり (Loop Closure なし):
  ステップごとに ε ~ N(0, 0.01²) の誤差が加算
  1000 ステップ後: σ_total = 0.01 × √1000 ≈ 0.32 m
  走行履歴と地図の整合性が崩壊

Loop Closure あり:
  ステップ 999 で「これは出発点だ」と認識
  制約: 出発点と現在位置の距離 = 0
  全軌跡を g2o で再最適化 → 誤差を全体に分散
  最終誤差: 0.05 m 程度 (ノイズの 5 倍程度に収束)

→ Loop Closure 検出は ORB-SLAM では Bag-of-Words 方式、最近は 学習ベース (NetVLAD 等) も

9. Sim2Real — Domain Randomization で Reality Gap を埋める

_

📐 数式

概要: Tobin et al. (2017) が提唱した、シミュレータ学習方策を実機に転移する技術。シミュレータパラメータを大胆にランダム化することで「無数の異なる物理世界」を経験させ、実機を「学習分布の一点」として扱う。OpenAI Rubik's Cube (2019)、ANYmal (2020)、NVIDIA Isaac Lab (2021〜) で標準化。

Domain Randomization の最適化問題:
$\pi^*_{DR} = \arg\max_\pi \mathbb{E}_{\theta \sim p(\theta)} \left[ J(\pi, \text{sim}_\theta) \right]$
  θ: シミュレータパラメータ（摩擦、質量、光源等）
  p(θ): 設計者が設定するランダム化分布

Reality Gap (転移誤差):
$\Delta = J(\pi^*_{DR}, \text{real}) - \mathbb{E}_{\theta} J(\pi^*_{DR}, \text{sim}_\theta)$

条件: 実機分布が学習分布に含まれる:
$\theta_{\text{real}} \in \text{supp}(p(\theta)) \implies \pi^*_{DR} \text{ は実機でも有効}$

$p(\theta)$ を学習中に自動拡張: 性能が一定以上なら範囲を広げ、未満なら狭める

→ 学習が進むに連れて「より頑健な方策」を獲得
→ Real2Sim2Real: 実機データで sim の θ を調整 → DR で再学習

10. SayCan — LLM の Say × アフォーダンスの Can

_

📐 数式

概要: Ahn et al. (Google Robotics, 2022) が提唱した LLM × ロボティクスの嚆矢。LLM (PaLM) の言語的妥当性スコアと、ロボットのアフォーダンスモデル (RL value function) の積で次の行動を選択。Symbol Grounding 問題への実用解として 2022-2023 年の研究を駆動した。

SayCan の選択則:
$\ell^* = \arg\max_{\ell \in \text{Skills}} \underbrace{p(\ell | i)}_{\substack{\text{Say}\\\text{(LLM)}}} \cdot \underbrace{p(c | s, \ell)}_{\substack{\text{Can}\\\text{(Affordance)}}}$

Say スコア: LLM が指令 i に対して尤もらしいスキル ℓ の言語確率
$p(\ell | i) = \text{LLM}(\ell | i, \text{prompt})$

Can スコア: 状態 s でスキル ℓ を成功させる確率（強化学習 V 関数）
$p(c | s, \ell) = V_\ell(s) \approx \mathbb{E}[\text{success of } \ell | s]$

事前学習スキル: ~100 個（find/pick/place/bring × 物体）
→ LLM は世界知識、アフォーダンスは物理可能性 → 積で接地
→ "Do As I Can, Not As I Say" の哲学を数式化

📊 グラフ（Say × Can による行動選択）

💡 解説

2022 年 4 月 PaLM-SayCan、Google Everyday Robots で実機実証
LLM × ロボティクス時代の幕開け、後の研究 1000+ 本の出発点
Symbol Grounding 問題への実用解（言語 × 物理可能性の積）
既存スキル + LLM で組み合わせ爆発を解放
事前学習 100 スキルの離散性、未知物体への対応不可
各ステップで LLM 推論 → 遅延、コスト大、計画の浅さ
💡 直感的に: LLM は「賢いが体がない頭脳」、ロボットは「体はあるが知識がない」存在。SayCan はこの 2 つを「Say × Can」で繋げる。LLM が "コーラ取って" と言いたくても、ロボットがコーラを認識できなければ実行されない（Do As I Can）。
💡 SayCan の革新: 古典 AI が 50 年苦闘した Symbol Grounding Problem（記号と現実の紐付け）への現代解。LLM = 記号主義、アフォーダンス = 結合主義 — この 2 つを掛け算で統合した。

11. LLM+P — LLM の翻訳力 × 古典 planner の最適性

_

📐 数式

概要: Liu et al. (MIT-IBM, 2023) が提唱した、LLM と古典 PDDL planner を分業させるフレームワーク。LLM は「翻訳役」（自然言語 ↔ PDDL）、planner は「最適化役」（A* / Fast Downward）。SayPlan (Rana 2023) は同じ発想を 3D Scene Graph 環境に拡張。

LLM+P のパイプライン:
$\text{NL指令} \xrightarrow{\text{LLM 翻訳}} \text{PDDL 問題} \xrightarrow{\text{Fast Downward}} \pi^* \xrightarrow{\text{LLM 説明}} \text{NL 出力}$

直接計画 vs LLM+P の成功率比較:
$\text{Acc}(\text{LLM 直接}) \approx O\left(\frac{1}{n^2}\right), \quad \text{Acc}(\text{LLM+P}) \approx 1 \text{ for solvable}$
  n: 問題サイズ（ブロック数等）

SayPlan の Scene Graph 圧縮:
$G_{\text{full}} \xrightarrow{\text{LLM フィルタ}} G_{\text{task}} \xrightarrow{\text{PDDL}} \pi^*$
  G_full: 全建物の 3D Scene Graph（数百ノード）
  G_task: タスク関連のサブグラフ（数十ノード）

分業の哲学: 自然言語 → 形式言語は LLM が得意、形式言語上の最適化は古典が得意
→ 古典 AI（PDDL, 1998）の現代復権の象徴

12. Code as Policies — Python コードでロボット制御

_

📐 数式

概要: Liang et al. (Google Robotics, 2022) が提唱したロボット制御パラダイム。LLM が自然言語指令から Python コードを生成し、それがロボットの Perception/Manipulation API を呼び出す。コードは数式・条件分岐・ループ・関数定義を自由に使え、PDDL より柔軟で自然言語より厳密。Voyager, AutoGPT 等の発想源。

Code as Policies の生成則:
$\text{code} = \text{LLM}(\text{prompt}_{\text{API}} + \text{NL指令})$

few-shot プロンプトの構造:
$\text{prompt}_{\text{API}} = \text{API ドキュメント} + \text{例 1} + \text{例 2} + \ldots$

階層的コード生成（複雑タスク）:
$\text{code}_{\text{top}} \to \{\text{code}_{\text{sub}_1}, \text{code}_{\text{sub}_2}, \ldots\} \to \text{API 呼び出し}$

API 例:
• Perception: detect_objects(color, category), get_pose(obj)
• Manipulation: pick(obj), place(obj, target), push(dir, dist)

→ コード = ロボット制御の中間表現（PDDL より柔軟、NL より明確）
→ LLM の学習データの 50%+ がコード → 最も得意な出力形式

    return f"Placed {len(red_blocks)} red blocks successfully"

13. VLA 基盤モデル — Vision + Language → 直接 Action

_

📐 数式

概要: Brohan et al. (Google DeepMind, 2023) の RT-2 を嚆矢とする End-to-End ロボット制御モデル。視覚 + 言語入力から、中間表現を経ず直接モーター指令を出力。Web 規模 LLM の知識をロボット行動に転移。OpenVLA (2024-06) でオープンソース化、π0 (2024-10) で Flow Matching 導入。

VLA の生成則:
$\pi(a_t | I_t, \ell) = \text{LLM}_\theta(I_t, \ell) \to a_t$
  I_t: 画像、ℓ: 言語指令、a_t: 7-DOF モーター指令

RT-2 の行動トークン化:
$a_t = [\Delta x, \Delta y, \Delta z, \Delta\phi, \Delta\theta, \Delta\psi, \text{grip}] \xrightarrow{\text{bin}_{256}} [t_1, \ldots, t_7]$
  256 段階の離散トークン → LLM 語彙に埋め込み

π0 の Flow Matching:
$\frac{da_t^{(s)}}{ds} = v_\theta(a_t^{(s)}, s, I_t, \ell), \quad a_t^{(0)} \sim \mathcal{N}(0, I)$
  s ∈ [0,1] のフローで連続行動を生成（Diffusion 派生）

事前学習: VL モデル（PaLM, Llama 2）を Web で → ロボデータでファインチューニング
→ Web 知識（"絶滅した動物"）がロボット行動に直接転移

📊 グラフ（VLA モデル比較）

💡 解説

2023 年 RT-2 が VLA パラダイムを確立、Web 知識転移を実証
2024 年 OpenVLA / π0 で研究コミュニティに普及
End-to-End 学習で中間表現の情報損失なし
Web 規模 LLM の創発能力（chain-of-thought, math, 物体知識）を継承
推論コスト（55B モデルで数百 ms）、リアルタイム制御に未達
ロボデータ枯渇、接触豊富タスク（組立・micro-manipulation）で性能落ち
💡 直感的に: 従来は「視覚 → 言語 → 行動」を別モジュールで処理した。VLA は「視覚 = 言語 = 行動」を 1 つのトークン列として扱う。LLM が "Hello" を生成するように、ロボットが "右に 10cm" を生成する。
💡 VLA の革新: SayCan や Code as Policies は「LLM + 外部エンジン」だったが、VLA は「LLM 自体がエンジン」。中間表現の人手設計を完全排除し、Web 学習がそのままロボット汎化に効く。

📖 詳細解説

① RT-2 の技術詳細（Google DeepMind 2023）

論文: RT-2: Vision-Language-Action Models Transfer Web Knowledge to Robotic Control
共同訓練データ: ロボデータ (RT-1, 130K traj) + Web (LAION, COCO 等)

行動の離散トークン化（核心アイデア）:
Action: [Δx=0.05, Δy=-0.02, Δz=0.10, Δϕ=0, Δθ=0, Δψ=0.5, grip=1.0]
   ↓ 各次元を 256 段階で離散化（上限-下限を 256 等分）
Tokens: [128, 102, 156, 128, 128, 192, 255]
   ↓ 既存 LLM 語彙の "special token" として埋め込み
LLM 出力:    ...
   ↓ デコードして連続値復元
Continuous Action: [0.05, -0.02, 0.10, 0.0, 0.0, 0.5, 1.0]
→ これにより既存 LLM をそのまま使える。Web の数十億 tokens の事前学習を完全流用

性能:

14. 世界モデル — Navigation World Models / Gemini Robotics-ER

_

📐 数式

概要: 2024 年に登場した「**未来を予測しながら動く**」ロボティクスの最先端。Bar et al. (Meta AI, NeurIPS 2024) の Navigation World Models が拡散モデルで未来画像を生成。Google DeepMind の Gemini Robotics-ER が物理直感 + Chain-of-Thought をロボット制御に統合。POMDP の信念計画が深層学習で復活した姿。

世界モデルの基本式:
$p(s_{t+1} | s_t, a_t) = \text{World Model}(s_t, a_t)$
  s_t: 状態（画像）、a_t: 行動、s_{t+1}: 予測される次状態

Conditional Diffusion による未来予測 (NWM):
$p_\theta(I_{t+1} | I_t, a_t) = \int p_\theta(I_{t+1} | I_t, a_t, \epsilon) \, p(\epsilon) \, d\epsilon$

Action Planning（H 手先まで予測）:
$a_t^* = \arg\max_{a_t} \sum_{h=1}^{H} \gamma^h \cdot V(\hat{I}_{t+h} | I_t, a_{t:t+h})$
  複数行動候補で未来をシミュレート、価値関数 V で評価

Embodied Reasoning (Gemini-ER):
$a_t = \text{LLM}_\theta(I_t, \ell, \underbrace{\text{CoT}}_{\substack{\text{Chain of}\\\text{Thought}}})$

パラダイム転換: 反射的 VLA → 予測 + 推論 + 行動 の三位一体
→ Mental Simulation を機械で実装、Bar 2024 の MuZero (2019) 系譜
