2. システム図

run_pipeline.py が 3 リポジトリを横断指揮。各ブロックを 🔧決定論 / 🎨生成LLM / 🧠評価LLM / 👤人手 でバッジ分け。VLM(🧠)も人手(👤)も Max 内（無課金）。

3. ワークフロー図とエージェントループ

各ノードを 🔧決定論 / 🎨生成LLM / 🧠評価LLM / 👤人手 でバッジ。◇＝ゲート（決定論）。🔁＝有界ループ（回数 cap → 人手へエスカレート）。🧠Claude が実際に介入するのは [3v] 生成QA・vlm.json 手書き・Tier-2 助言の3点だけ。

3.1 エージェントループの本質（生成器 ≠ 評価者）

上の縦フローを「ループ」だけ抜き出すとこの循環。🎨生成器(Gemini) が作り、別レイヤの 🔧+🧠+👤 評価器が判定。生成器が自分の画像を「良い」と判定して loop を閉じることは決してない＝自己消費 i2i 崩壊を構造で防ぐ。

4. 検証の3層と発動条件 🆕

鉄則：評価は生成器(Gemini)・配置器(scene-lib) と"非相関"な信号で行う（自分の出力を自分で合否判定しない）。⚠ 第2の Gemini を評価者にしない（癖を共有＝非相関でない）。

構造（公式の置き場）：エージェント"定義"は .claude/agents/placement-evaluator.md（再利用可能な subagent。ルブリック＝その system prompt）。workflows/placement_eval.wf.js はオーケストレーション専任（ファンアウト/集約/人手回送）で agentType:'placement-evaluator' から定義を参照。scene は args でパラメータ化済み＝再利用可。常設に残るのは1点：run_pipeline から「VLM評価ジョブをキュー→対話/Workflow が拾う」起動（claude -p は課金なので直接 spawn しない）＝ HARNESS_AUDIT.md STEP5。
実証：A2S2 全12頁で独立評価を実走 → page03 P1 の縦書きナレ"コマ上枠越え"を捕捉（決定論の盲点）。→ Tier-1 に「コマ上下枠越え」軸を追加＋fallback パネル枠を実マージン基準に修正し、p03 を修正・全頁 PASS（p08 既知のみ）。
要点：生成器（🎨Gemini）は自分の出力を単独で合否判定しない（→ ループの全体像は §3.1 図）。判定は必ず ① 🔧決定論ゲート（qa_*）か ② 👤人手。🧠Claude は助言のみ。ループは全て有界（回数 cap → 人手にエスカレート）。VLM 解析も人手レビューも対話セッション＝Max 内・無課金。今後の改善（CAS・run manifest・三層ゲート等）は HARNESS_AUDIT.md §3・§5。
